## 윈도우판 큐 규칙 (그대로 재현할 것)
- `add_item`: **pointer>0(붙여넣기 진행 중)** 이거나 **직전 복사로부터 idle_reset_sec(기본 10초) 경과**면 큐를 비우고 새로 시작, 아니면 뒤에 누적. 매번 마지막 복사 시각 갱신.
- `get_next`: pointer 위치 항목을 주고 pointer+1. 소진이면 nil(아무것도 안 함).
- `mark_plain_paste`/`clear`: 일반 ⌘V(물리 키)면 큐 비움. 소진 완료 시에도 비움.
- `remove_item(id)`: 히스토리에서 지운 항목을 큐에서도 제거, 이미 지나간 항목이면 pointer도 1 감소.
- `get_status` → (pointer, total), idle 값은 설정에서 바뀌면 즉시 반영.
- (윈도우판의 `undo_last`, `set_queue`는 지금 앱에서 쓰이는지 확인 후 필요할 때만.)

## DB 규칙
- 히스토리 50개 FIFO, 고정(pin) 항목은 제한 제외, pin_order로 정렬.
- 항목: 종류(텍스트·이미지·HTML·RTF 등), 원본 형식 보존(맥은 NSPasteboard의 type별 데이터를 모두 저장), 미리보기 글자, 썸네일, 생성 시각, 고정 여부, 저장된 이미지 경로.
- 직전 항목과 내용이 같으면(해시) 중복 추가하지 않음. 자기 자신이 클립보드를 바꾼 경우는 무시.

## 할 일
1. `PasteFlowCore`에 큐·DB 로직을 테스트 먼저 작성(`swift test`). DB는 SQLite3(시스템 라이브러리) — 새 패키지 들이기 전에 시스템 것으로 되는지 먼저 확인.
2. 맥 클립보드 감시: NSPasteboard는 변경 알림이 없어 `changeCount` 주기 확인(폴링)이 일반적 — 간격·CPU 부담을 실측해 정한다.
3. 감시 → DB 저장 → 큐 추가까지 연결하고, 메뉴바 메뉴에 임시로 "최근 항목 n개 / 큐 n/total"을 보여 실제 복사로 확인.

## 끝의 기준
