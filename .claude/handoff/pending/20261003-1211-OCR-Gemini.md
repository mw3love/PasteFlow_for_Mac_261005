- 인터뷰 결정: OCR은 "처음부터 Gemini"(맥 내장 Vision은 ko-KR 지원 실측했지만 사용자 선택은 Gemini). 윈도우판도 v1.28부터 Gemini 고정.
- 윈도우판 참고: https://github.com/mw3love/Paste_flow `pasteflow/ocr_engine.py`(게이트웨이 호출·폴백·probe), `main.py`의 OCR 결과 처리(`_persist_clipboard_item`, OCR 결과 자체 토스트), `ui/ocr_overlay.py`.

## 윈도우판 OCR 사실 (코드에서 확인)
- OpenAI 호환 게이트웨이(mindlogic). `base_url`에 `/chat/completions` 등을 붙여 넣어도 잘라내 정규화(`_normalize_base_url`).
- **Cloudflare가 기본 UA를 봇으로 보고 403(code 1010) 차단** → 브라우저형 User-Agent를 붙인다.
- 모델 기본 `gemini-2.5-flash`, 폴백 `gemini-2.0-flash`. 이미지를 못 받는 모델의 400은 별도 판정. 설정에 "모델 확인(probe)" 기능.
- 설정 키: `ocr_gemini_base_url`, `ocr_model_gateway`, API 키는 DPAPI 암호화(맥은 **키체인**으로 — PLAN.md).
- 크레딧 잔액 `GET {base_url}/credits/`(mindlogic 전용).
- OCR 결과는 클립보드 + 히스토리 + 큐(복사와 같은 무중복 경로) + 결과 미리보기 토스트.

## 할 일
1. `⌘⇧E`를 `Hotkeys.screenAction`에 추가(키 코드 E=14), 테스트.
2. 캡처 오버레이 재사용: `CaptureOverlay`에 "OCR 모드"(결과 PNG를 저장·클립보드 대신 OCR로 넘김).
3. `PasteFlowCore`에 게이트웨이 요청 만들기(base_url 정규화, 요청 본문, 응답에서 글자 꺼내기)를 테스트로 — 네트워크는 URLSession, 외부 패키지 없이.
4. API 키·base_url·모델 입력: 9단계 설정창 전이라 임시로 메뉴바 메뉴 "OCR 설정…"(키체인 저장) 정도. 키 값은 사용자가 직접 입력(대화에 붙여넣게 하지 말 것).
5. 결과: 글자를 클립보드에 올려 감시기가 히스토리·큐에 넣게 하고(캡처와 같은 방식), 토스트에 앞부분 미리보기. 실패 시 이유를 토스트로(키 없음·네트워크·모델 거부).
