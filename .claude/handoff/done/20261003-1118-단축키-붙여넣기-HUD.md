# 4단계: 단축키 감시·붙여넣기 주입 + 진행 HUD

## 만들 것 (PLAN.md 단축키 표 그대로)
- `⌘⇧V` 순차 붙여넣기: `queue.next()` → 그 항목의 모든 형식을 클립보드에 씀 → `monitor.noteSelfChange()` → ⌘V 주입. 소진이면 아무것도 안 함(키만 삼킴).
- `⌥⌘⇧V` 전체 자동: 남은 항목을 간격(윈도우판 300ms) 두고 차례로 주입.
- `⌃⌘V` 경로 붙여넣기(하나) / `⌃⌥⌘V`(전체): 이미지면 임시 PNG(예: `$TMPDIR/PasteFlow/`)로 저장 후 절대경로 글자로, 그 외는 원본 그대로. 같은 큐 공유. 임시 파일 정리 방식도 정할 것.
- 일반 `⌘V`(사용자가 직접 누른 것) 감지 → 큐 비움. **앱이 주입한 ⌘V는 제외**해야 함(윈도우판은 LLKHF_INJECTED 플래그; 맥은 이벤트 출처 PID나 `eventSourceUserData` 표식으로 구분 — 방식 실측으로 확인).
- 진행 HUD: 포커스를 뺏지 않는 창(NSPanel nonactivating), 우하단, `순차 붙여넣기 n/total` + ✓(완료·흐림)/▶(다음·강조)/·(대기) 목록 + ✕ 취소. 소진 시 1.2초 뒤 사라짐(fade). 디자인은 PLAN.md "디자인 테마" 토큰.
- 큐 비우기 공통 경로: 일반 ⌘V·소진 완료·✕ 취소가 같은 함수를 쓰게.

## 맥에서 확인할 함정
- 전역 키 가로채기는 `CGEventTap`(손쉬운 사용 권한 — 이미 허용됨). 맥이 감시가 느리다고 판단하면 탭을 꺼버린다(`tapDisabledByTimeout`) → 다시 켜는 처리 필수.
- 한글 입력 상태에서도 동작해야 함 → 글자가 아니라 키 코드(V = 9)로 판정.
- **Karabiner-Elements 실행 중** — 키 재매핑과 겹치는지 실측.
- 주입 직후 붙여넣기 전에 클립보드가 덜 바뀌는 타이밍 문제 가능 → 실측.

## 끝의 기준
- 메모장류 앱(TextEdit)에서 A·B·C 복사 후 `⌘⇧V` 세 번 → A·B·C 순서로 붙음, 네 번째는 아무 일 없음.
- 중간에 일반 `⌘V`를 누르면 큐가 비워짐(HUD 사라짐), 주입한 ⌘V로는 안 비워짐.
- 이미지 복사 후 `⌃⌘V` → 터미널에 PNG 절대경로가 붙고 그 파일이 실제로 열림.
- HUD가 진행에 맞춰 바뀌고 포커스를 뺏지 않음 — 스크린샷으로 확인(터미널 화면 기록 권한 있음, 단 Chrome 전체 화면이면 메뉴바·위치 주의).
